# Comparability: most extracted bounds are never compared

Written 2026-11-11. Numbers: [`data/reports/profile-coverage.md`](../data/reports/profile-coverage.md),
generated by `pipeline/profile_coverage.py`.

## The problem

The atlas exists to put bounds side by side. A bound takes part in a setting's status (tight / gap /
conflict) only if it has a **growth profile**: exponents in the scanned variables T, K, d, 1/Δ, 1/ε. And it
gets one only if it is written entirely in canonical variables.

**27% of extracted bounds have a profile (1,282 of 4,700).** The other 73% are shown on the site but never
compared. Every status the atlas reports, tight or gap, rests on that minority. This could be the central
weakness of the whole approach: extraction works, organisation by setting works, but most of what is
organised cannot be compared.

## Why bounds are not profiled

| reason | results |
|---|---|
| a symbol outside the canonical registry | 3,204 (68% of all results) |
| no scanned variable (e.g. a constant bound) | 90 |
| numeric fit failed | 50 |
| runaway exponent (`log(T)**(d+1)`, `exp(-Δ²T/K)`) | 48 |
| only opaque symbols (`gamma_T`, `C_lin`) | 26 |

So the question is about the foreign symbols. There are 2,519 distinct ones, a very long tail: the most
frequent, `rho`, appears in 95 results from 40 papers. Names are overloaded across papers: `rho` is a
perturbation size, a smoothness rate or a failure probability depending on the paper. The extractor
declares a one-line meaning for each, so a random sample of 200 such results (397 symbol occurrences) was
classified from those meanings by one LLM call.

**Are they unresolved names, or genuinely different quantities? Mostly genuinely different.**

| per result (the worst symbol decides) | of 200 |
|---|---|
| has a genuinely different problem parameter | 172 (86%) |
| needs the tuned value of an algorithm parameter | 11 (6%) |
| an alias of a canonical variable, or a constant | 9 (4%) |
| a derived quantity that could be expanded (e.g. ρ = B/T) | 6 (3%) |
| a round index or misuse | 2 (1%) |

Better name resolution would rescue about 7%, roughly 250 bounds. The rest really do depend on something
other than T, K, d, Δ, ε. Examples:
- **class complexity:** zooming dimension, eluder dimension, Natarajan dimension;
- **instance constants:** a GLM link constant κ, a norm bound S, a minimum probability p_min;
- **structure sizes:** matroid ground set, number of edges, number of players or tasks;
- **non-stationarity budgets:** path length P_T, variation V_T;
- **paper-specific hardness quantities:** D*(c, U), I*(ν), Σ Γ²_{ij}/(Δ_i²Δ_j²).

## Three layers of the problem

1. **Naming** (≈7%). The same quantity under another name (`n` = number of arms), or a constant. This is
   an extraction and registry problem with a mechanical fix.
2. **Parameterisation** (most of it). The bound depends on a property of the problem that the setting
   does not fix. Whether the bound can be compared with others depends on how that property behaves:
   - a **fixed factor**, independent of T, K, d (κ·d·√T, S·√(dT)): 109 of the 172. It can be held fixed and
     the rest compared, just as constants are ignored now. The comparison is then "tight up to instance
     parameters", which is weaker than "tight up to constants" and has to be labelled so.
   - **in an exponent** (T^{(d_z+1)/(d_z+2)}): 21. The rate itself depends on the parameter. It can only
     be compared with bounds in the same parameter, as a function of it.
   - **growing with T or another scanned variable** (path length, cumulative loss, a ground-set size that
     scales with K): 19 by a crude keyword test, probably more. Holding these fixed is wrong. The two
     zhou2025learning conflict cells come from exactly this, with the switch count S_T held fixed.
3. **Genuinely different measures.** Bounds in terms of a paper's own complexity quantity are comparable
   only with bounds in the same quantity, or after a conversion (e.g. eluder dimension ≤ d for linear
   classes). That is the fragmentation problem in another form: 94% of settings come from one paper, and
   many bounds come in their own units.

## Why it matters beyond this project

This is the comparability problem every attempt to organise results runs into. Leaderboard extraction found
that results are hard to compare across papers even when values are extracted correctly (e.g. "No One
Knows the State of the Art in Geospatial Foundation Models", arXiv:2605.12678). Theory is better placed,
because bounds are formulas and relations between quantities are often theorems. But it means an atlas's
value is set less by how much it reads than by how much of what it reads it can relate.

## Options

1. **Hold instance constants fixed** (trying now). Classify each (paper, symbol) once, cached like
   `condition-classes.yaml`, as: constant, instance constant, alias of a canonical variable, grows with a
   scanned variable, tuning, derived, or misuse.
   - Hold constants and instance constants fixed, unless they appear in an exponent.
   - Substitute aliases.
   - Leave everything else unprofiled.
   - Mark a cell whose front relies on a held-fixed parameter as **conditional** ("up to instance
     parameters"), so a tight label can't hide a κ- or S-dependence.

   Expected gain: on the order of 1,500 more profiled bounds. Risk: misclassifying a growing quantity as
   fixed, which creates false tight cells or false conflicts. The conflict count is the alarm.
2. **Grow the registry** with recurring parameters (zooming dimension, path length, number of players,
   budget, delay, eluder dimension, κ), scanned as further variables where they define a regime. This is
   more work per parameter, but it gives real comparisons, e.g. dynamic regret in P_T.
3. **Conversions**: theorems relating quantities (eluder ≤ d for linear, the kernel information gain γ_T
   per kernel family, α(G) ≤ K). This is where an expert's knowledge enters as data; it overlaps with the
   ontology review's `kernel.family` proposal.
4. **Tuned values**: when a bound holds for any tuning, record the paper's recommended tuning and
   substitute it (the extractor already stores `tuning`).
5. **Extraction guidance**: ask the extractor to state each bound in canonical variables when the paper
   also does (many papers give a corollary "with κ = O(1)").

## Open questions

- Is "tight up to instance parameters" a useful status for readers, or does it dilute "tight"? Experts may
  care exactly about the κ-dependence (cf. the logistic-bandit literature, where removing κ was the result).
- Should the atlas report coverage per cell: how many of the setting's bounds were compared?
- Which recurring parameters deserve to be scanned variables (option 2)?
